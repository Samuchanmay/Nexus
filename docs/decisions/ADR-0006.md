# ADR-0006 · Zona horaria fija: America/Merida

**Estado:** Aceptado.

## Contexto

El negocio ocurre en una sola zona horaria. El reloj del cliente no debe decidir qué es "hoy" (fichaje, saldos, reportes), y `new Date()` a secas en Edge Functions produce sesgos.

## Decisión

Todas las fechas de negocio se computan en **`America/Merida`** (`src/lib/tz.ts` en cliente; zona fija en las Edge Functions `gcal-*`, `fichar`, `notify-vacation`).

## Consecuencias

- "Hoy" es inequívoco para el equipo completo.
- Los timestamps se guardan ISO y se formatean a la zona en la capa de presentación.
- La regla está en `AI_RULES.md` (nunca depender del reloj del cliente para negocio).
- Si algún día la organización cambia de zona, se toca un único lugar (tz + funciones).
