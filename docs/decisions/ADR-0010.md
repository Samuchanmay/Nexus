# ADR-0010 · Tailwind + tokens CSS (design tokens reales, no clases sueltas)

**Estado:** Aceptado.

## Contexto

El rebrand dejó un sistema visual rico: temas claro/oscuro, acento azul, paleta semántica, radios, sombras y curvas. Se necesitaba una forma coherente de aplicarlo sin hex sueltos ni utilidades ad-hoc.

## Decisión

- **Tokens CSS en `globals.css`**: `:root` (claro) y `[data-theme="dark"]` — `--accent`, neutros Apple, `--ok/--warn/--danger/--purple` con `-tint`, `--radius-l/m/s`, `--shadow-1/2/3`, `--ease/--spring`, escala `--fs-*`, paleta `--ev-*`, mesh por rol (`data-mesh`).
- **Tailwind 3.4** para utilidades; los valores de diseño se refieren a los tokens (`var(--...)`), nunca hex/movimientos sueltos.
- El workspace del chat remapea tokens en su scope `.chat-ws`.

## Consecuencias

- Cambiar el tema = cambiar tokens; la UI se re-pinta sola.
- Consistencia de colores/radios/sombras en toda la app.
- Regla dura para agentes: no introducir colores fuera del token (ver `AI_RULES.md`).
- Ver `docs/design/DESIGN_SYSTEM.md`, `docs/design/COLORS.md`.
