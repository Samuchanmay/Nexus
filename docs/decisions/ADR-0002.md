# ADR-0002 · Single-tenant

**Estado:** Aceptado · **Nota:** ver también migración `0011_enlace_mvp.sql`.

## Contexto

Emet nace para una organización concreta (Cert). Diseñar multi-tenant desde el día uno añade costo a cada RLS, trigger y consulta.

## Decisión

Empezamos **single-tenant**: una organización, un proyecto, un dominio institucional (`@cert.edu.mx`), una zona horaria (`America/Merida`). El schema NO tiene `organization_id` en las tablas aún.

## Consecuencias

- RLS más simple (por rol/jerarquía, no por organización).
- Edge Functions asumen la zona y el correo institucional fijos.
- El código DEJA constancia: `0011_enlace_mvp.sql` documenta la intención de futuro `organization_id` si se va multi-tenant.
- Migrar a multi-tenant más tarde es un proyecto con migración de datos y RLS — no se hace a la ligera.
